# Changelog

Все заметные изменения проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [2.0.0] — 2026-11-21

Полная пересборка passrw-bot на async-стеке: один процесс (aiogram 3 + FastAPI +
SQLAlchemy 2 async + SQLite WAL) вместо трёх процессов, файловых флагов и потока
на каждый трекинг.

### Добавлено

- Бот: пошаговый поиск (станции → календарь окна продажи → пассажиры → поезд),
  трекинг поезда, несколько трекингов, фильтры (вагон, цена, порог мест),
  тихие часы, heartbeat, история мест и цен, история поисков, избранное, статистика,
  понятные причины пустой выдачи.
- Команды `/start`, `/help`, `/track`, `/mytracks`, `/status`, `/stop`, `/history`,
  `/favorites`, `/stats`, `/settings`, `/privacy`, `/admin`, `/cancel` работают
  в любом состоянии диалога.
- Админка: дашборд, карточка и фильтры трекинга, история замеров, управление
  пользователями (блокировка, роли, рассылка), логи, экспорт CSV, `/healthz`, `/metrics`.
- Надёжность: ретраи, кэш и семафор HTTP-запросов, детект капчи, сигнал
  «вёрстка изменилась», адаптивная частота проверок, алерты администратору.
- Супервизор задач трекинга с бэкоффом, джиттер старта после перезапуска,
  атомарное создание трекинга, лимит размера ответа и ограничение словаря локов.
- Инфраструктура: GitHub Actions (Python 3.12/3.13 + coverage-гейт), MIT LICENSE,
  `.editorconfig`, pre-commit, Dependabot, скрипт резервного копирования SQLite,
  усиленный `docker-compose.yml`.

### Изменено

- Окно продажи вынесено в `SALE_WINDOW_DAYS` (по умолчанию 60 дней) и ограничивает календарь.
- Callback-данные кнопок содержат `search_id`: устаревшие поиски отклоняются.
- Пагинация списков клампится, flash-сообщения показываются один раз.
- Уведомления и heartbeat учитывают тихие часы пользователя; истечение трекинга
  деактивирует запись и не будит пользователя ночью.

### Исправлено

- Обход `IP_WHITELIST` поддельным `X-Forwarded-For`; доверие только `TRUSTED_PROXIES`.
- HTTP 500 на не-ASCII логине, CSRF-токене и идентификаторах записей.
- HTTP 500 на `page=10**19` в `/trackings` и `/users`; верхняя граница `heartbeat_interval`.
- Гонка двойного создания трекинга при одновременных callback.
- «Тихая смерть» задачи трекинга при неожиданном исключении.
- Утечка локов HTTP-клиента при `HTTP_CACHE_TTL=0` и отсутствие лимита ответа.
- Регрессия распознавания «станция не найдена» в парсере.

### Безопасность

- Выход и смена пароля/хеша отзывают все активные сессии (эпоха в `app_meta`).
- Сравнение логина/CSRF без утечки по времени и без падения на не-ASCII.
- CSRF для изменяющих запросов, HttpOnly/SameSite=Lax cookie, `no-store`,
  CSP `script-src 'none'`, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`,
  HSTS при `SESSION_COOKIE_SECURE=true`.
- Блокировка входа и rate limit, экранирование HTML, защита CSV от формул,
  валидация станций, дат, идентификаторов и числовых фильтров.
- Страница ошибки не раскрывает секреты и внутренние детали.

### Миграция

- Старая база импортируется скриптом `scripts/import_legacy.py`.
- Схема создаётся автоматически; служебная таблица `app_meta` хранит отпечаток
  учётных данных и эпоху сессий.
